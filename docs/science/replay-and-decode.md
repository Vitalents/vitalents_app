## DECODE adapter

Call `science.decode.verify(session, events, subject=subject, key_registry=registry, expected_event_ids=sealed_ids)`. The registry gives the immutable nine-symbol permutation for the session key version. The trusted capture seal lists every emitted event ID in capture order, including rejected attempts. Use immutable or independently verified record revisions. The verifier checks ledger membership, row identity, scope, trial sequence, outcome and timing, and recomputes the score. A seal derived from the received rows cannot reveal a dropped row. The replay constructs the seal directly from the synthetic capture, then tests removal against the original seal.

- The provisional QA convention uses measurement-relative monotonic milliseconds, a completed window of exactly 90,000 ms, and the half-open interval [0, 90000). The deadline itself is late. Normalize phase and time origin at capture. A verified UTC adjustment may preserve scoring through the Task 3 gate. Task 4 separately guards reference ordering.
- Trial indices start at 0. First response wins for each sequential stimulus. A later in-window press against the same accepted trial is a duplicate, while a press at or past the deadline is late. Exact and conflicting event-ID replays both fail verification. Terminal unanswered trials retain a missed or interrupted row. Completed accepted trials require foreground capture and the declared session input method.
- Accepted attempts equal correct plus incorrect. Accuracy is 100 × correct / accepted. Median RT uses only accepted correct trials and subtracts stimulus time from response time. A small absolute tolerance of 0.0000001 ms accounts for binary representation in RT claims. There is no speed-based rejection threshold. Use `event_counts` for separate missed, late, duplicate and interrupted counts. Treat `issues` as ledger or input inconsistencies.
- A verified empty ledger yields zero counts and undefined accuracy and median. If every accepted answer is wrong, accuracy is 0% and median correct RT is undefined. An unverified or unfinished session has no published summary. A verified practice session returns feedback as `practice_only` and stays outside personal references. Preserve repeats as separate sessions.
- Use the verifier result for score publication and pass its ledger attestation to Information Status together with the original verified record and any trusted clock context. The result describes game performance. A valid ledger still needs a comparable context and sufficient history for a reference.

These conventions apply to the standalone verifier. The browser app follows the current data contract; adapters must reconcile the two protocols explicitly. Use an independently captured browser/device trace to verify timer origin, visibility or focus interruptions, key mapping, and phase order from preparation through measurement to story/reward. Verify score formatting without rounding the persisted computation. The original standalone package did not evaluate browser/device capture; its results cannot establish timing validity on target devices.
